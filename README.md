# 电商用户行为运营分析（淘宝用户行为日志）

这是我为数据运营岗准备的作品集项目。数据来自阿里云天池的淘宝用户购物行为数据集（dataset 649），覆盖 2017-11-25 到 12-03 共 9 天。Python 负责抽样和入库，SQL 做清洗和五块分析，最后用 Pyecharts 出了四张看板。

分析下来有两个结论我想单独说。一个是最大流失环节其实在加购到购买，不在浏览到加购，和直觉相反。另一个是这份公开数据的 cohort 留存算不出可信结果，排查后确认是数据本身的性质，所以没当留存结论用，改以数据质量诊断的形式保留，过程写在 5.5 节。

## 二、抽样口径

按用户等概率简单随机抽样。把去重后的全部 user_id 排好序，用 `random.seed(42)` 固定种子后 shuffle，取前 10%。是精确的 10%，`random() < 0.1` 那种近似不算。

| 指标 | 实测值 |
|---|---|
| 全量用户数 | 987,994 |
| 抽样用户数 | 98,799 |
| 实际抽样占比 | 10.0000% |
| 抽样行数 | 10,023,087（不含表头） |

抽的是人，不是行。按行抽的话，行为越多的用户越容易被抽中，而且同一个人的浏览、加购、购买会被打散到不同样本里，漏斗和留存就全废了。按用户抽能保住每个人的完整行为链，比率类指标（转化率、留存率）在随机抽样下无偏；总量类指标就按抽样口径报告。

种子固定之后，`data/UserBehavior_sample.csv` 生成即冻结，任何时间重跑拿到的用户和数字都一样。

导入 MySQL 的表叫 `user_behavior_sample`（10,023,087 行，不含表头），后面所有 SQL 都查它。

## 三、数据清洗

数据集官方口径是 2017-11-25 到 2017-12-03 共 9 天。但原始文件在窗口外还有 5,569 行，大部分是紧邻窗口的日期（2017-11-01 至 11-24、2017-12-04 至 12-14），也有明显离群的时间戳（1979-03-16、2017-04、2018、2025-11-03）。我按官方口径裁到 9 天内。不裁的话，窗口外的记录会把用户的"首次行为日"挤到 11-25，留存的注册日就脏了。

被剔掉的 5,569 行按日期分段如下。

| 性质 | 行数 |
|---|---|
| 时间戳为负 | 14 |
| 早于 2017-11-07（含 1979、2017-04 等离群日期） | 227 |
| 2017-11-07 ~ 11-24（窗口前） | 5,120 |
| 2017-12-04（窗口后当天） | 116 |
| 2017-12-05 及以后（含 2018、2025 离群日期） | 92 |
| 非法行为类型 | 0 |
| 非法类目（category_id ≤ 0） | 0 |
| 合计 | 5,569 |

非法行为类型和非法类目这两个过滤条件我留在了 SQL 里，不过这份抽样集里一行都没命中。

清洗后剩下 10,017,518 行、98,798 个用户，日期范围正好 9 天。各行为的分布：

| 行为 | 行为数 | 去重用户数 |
|---|---|---|
| 浏览(pv) | 8,976,117 | 98,435 |
| 加购(cart) | 552,395 | 73,831 |
| 收藏(fav) | 288,176 | 39,038 |
| 购买(buy) | 200,830 | 67,319 |

## 四、核心指标口径

| 指标 | 定义 |
|---|---|
| PV / UV | `pv` 行为总次数 / 去重 `user_id` 数 |
| 序列漏斗三环节 | 以各行为的最早发生时间为准，要求时序依次发生：`t_pv < t_cart < t_buy`。第 N 环节成立的前提是第 N-1 环节已经成立、且发生在它之前 |
| 浏览→加购 转化率 | 加购环节用户数 / 浏览用户数 |
| 加购→购买 转化率 | 购买环节用户数 / 加购环节用户数 |
| 全链路转化率 | 购买环节用户数 / 浏览用户数 |
| 环节流失率 | 1 减该环节转化率 |
| 用户付费率 | 购买用户数 / 总用户数（用户级口径） |
| 事件级 PV→购买转化率 | 购买次数 / PV 次数（事件级口径，可以和行业页面级指标对比） |
| R 档（近度，5 档） | 最近一次购买距分析末日（2017-12-03）的天数：≤1天=5档，≤3天=4档，≤7天=3档，≤15天=2档，>15天=1档 |
| F 档（频次） | 9 天内购买次数：≥5次=5档，3-4次=4档，2次=3档，1次=2档，0次=1档 |
| 高价值用户 | R≥4 且 F≥4，即最近 3 天内购买过、且 9 天内购买 3 次以上 |
| 高价值用户贡献度 | 高价值用户购买次数 / 全体用户购买次数（数据集没有金额，用购买次数近似） |

漏斗我按序列算，没有简单统计"有多少人分别做过 pv、cart、buy"。后者算出来是集合并集，而这份数据里实测有 14,206 个人从未加购却直接买了东西。按并集口径，这些人会全部落进"浏览→加购"的流失里，卡点判断会整个反过来。要求时序依次发生后，漏斗才反映真实路径上的流失。

R 档的可观测范围受窗口长度限制。9 天里 R 最大只能到 8，所以 15 天那一档空着，实际只观测到 5/4/3/2 四档，`03_2.csv` 里原样呈现了这个结果。

## 五、分析结论

下面每个数字都能在 `results/` 里找到对应的 CSV。

### 5.1 转化漏斗

| 环节 | 用户数 | 转化率 | 流失率 |
|---|---|---|---|
| 浏览 → 加购 | 98,435 → 67,083 | 68.15% | 31.85% |
| 加购 → 购买 | 67,083 → 30,925 | 46.10% | 53.90% |
| 全链路（浏览→购买） | — | 31.42% | — |

最大卡点在加购→购买。加购前流失了 31,352 人，加购后又有 36,158 人没买，流失率 53.90%，几乎是前者的两倍（数据在 `02.csv`、`02_2.csv`）。所以运营重点应该放在购物车挽回上：加购未购用户的催付提醒、限时优惠、库存和价格变动提醒。浏览→加购那 31.85% 的流失也没法忽略，可以用详情页的加购引导接一接。

### 5.2 收藏作为平行信号

| 类型 | 用户数 | 购买转化率 |
|---|---|---|
| 收藏用户 | 39,038 | 71.19% |
| 未收藏用户 | 59,760 | 66.15% |

收藏用户的购买转化率比未收藏的高约 5 个百分点，是个正向信号（`02_3.csv`）。主路径我用了加购，因为加购在时序上离付款更近；收藏单独拎出来做对比。

### 5.3 RF 用户分层

| 分层 | 用户数 | 用户占比 | 购买贡献占比 |
|---|---|---|---|
| 高价值（R≥4且F≥4） | 23,591 | 35.04% | 62.42% |
| 潜力（R≥3且F≥3） | 19,951 | 29.64% | 25.17% |
| 普通 | 23,777 | 35.32% | 12.42% |

35.04% 的高价值用户贡献了 62.42% 的购买次数，头部集中比较明显（`03.csv`）。这个群体适合做专属召回，比如复购推送和会员权益。

R 档位分布见 `03_2.csv`，和 `03.csv` 是同一个 R 口径：5档 30,214、4档 15,688、3档 18,520、2档 2,897，1 档没有用户。

### 5.4 时段分析

24 小时分布上，晚 19-22 点是高峰，四小时合计占全天 PV 的 30.14%，峰值落在 21 点（758,098 次浏览、66,257 个用户）。凌晨 4-5 点最冷清。

一周分布得按日均比（`05_2.csv`）。9 天窗口里周六周日各出现 2 次、周一到周五各出现 1 次，直接比 PV 合计的话周末会显得是工作日的两倍多，其实那是天数效应，不是行为差异。换成日均：周六 1,081,428、周日 1,088,878，工作日日均 927,101，约 1.17 倍。再把窗口末尾两个活跃度突变的日子（12-02、12-03，原因见 5.5）剔掉，周六（11-25）935,165、周日（11-26）952,609，和工作日日均 927,101 基本没差别。

所以这份数据撑不起"周末更活跃"这个说法。能用的日内规律只有一条：晚间 19-22 点。活动排期和推送集中在这个时段，触达效率最高。

### 5.5 留存分析：一次数据质量诊断

以用户首次行为日近似注册日（数据集没有注册字段），算次日、3 日、7 日留存。窗口外的档位我输出空值，不写 0，因为"观测不到"和"观测到了但没人留存"是两回事。

| 注册日 | 注册用户数 | 次日留存 | 3日留存 | 7日留存 |
|---|---|---|---|---|
| 11-25（首日） | 70,625 | 78.91% | 75.77% | 98.53% |
| 11-26 | 15,733 | 65.63% | 66.29% | 97.25% |
| 11-27 | 6,368 | 61.56% | 63.96% | 窗口外 |
| 11-28 | 3,222 | 61.42% | 66.33% | 窗口外 |
| 11-29 | 1,830 | 68.14% | 96.28% | 窗口外 |
| 11-30 | 998 | 93.99% | 94.69% | 窗口外 |
| 12-01 | 20 | 90.00% | 窗口外 | 窗口外 |
| 12-02 | 2 | 100.00% | 窗口外 | 窗口外 |

这份数据的 cohort 留存解释不了真实留存，所以我没有从中提取任何留存结论。排查分三步。

第一步看形状：留存曲线根本不递减，而是随日历跳。7 日留存 98.53% 比次日留存 78.91% 还高，3 日留存 96.28%、次日留存 93.99% 也都不正常。这些高值只出现在"注册日 + N 恰好落在 12-02 或 12-03"的时候。

第二步找原因：数据集末尾两天接近全员活跃。12-02 有 97,021 个用户活跃，占全部 98,798 人的 98.2%；12-03 是 96,676 人，97.9%。

第三步排除自身问题：会不会是我的抽样或者代码出了错？我把 3.67GB 全量原始数据完整扫了一遍，12-02 有 941,709 人活跃、95.32%，结论一样。所以这是数据集本身的特性。

再加一条佐证：99.87% 的用户末次活跃都落在窗口最后两天，而只有 2 个人是首次出现在最后两天。这说明这份数据的用户抽样框锚定在窗口末尾，不是在 9 天里均匀展开的。

于是 11-25 cohort 那个 98.53% 的 7 日留存，真实含义是"这批人在窗口最后一天几乎都被观测到了活跃"，而不是"用户回来了"。这一项我留在项目里当数据质量诊断，没当成留存成绩写进结论。

### 5.6 类目分析

这里的 PV 转购买率是事件级口径（购买次数 / PV 次数），和 5.1 的用户级漏斗不是一回事，两者不能换算（`06.csv`、`06_2.csv`）。

高曝光但转化差的几个：2355072（317,081 PV）只有 0.389%；3607361（298,508 PV）0.429%；4756105（447,776 PV，曝光量最大）0.625%。

转化好的几个曝光量都在中等水平：2885642（95,124 PV）3.298%；2735466（110,211 PV）3.024%；2640118（71,849 PV）2.502%。

头部曝光类目的转化率明显低于整体，详情页、定价、流量分配这几处都有优化空间；反过来，那几个高转化类目值得加流量。

## 六、运营建议

1. 购物车挽回优先。加购→购买流失 53.90%，36,158 人加购后没买，是全链路最大的漏点。建议对加购未购用户做催付提醒、限时优惠券、降价和库存提醒。
2. 详情页加购引导。浏览→加购还有 31.85% 流失，可以优化加购入口和商品卖点呈现。
3. 高价值用户专属召回。35.04% 的用户贡献 62.42% 的购买，做复购推送和会员权益的 ROI 最高。
4. 黄金时段排期。晚 19-22 点占全天 PV 的 30.14%，促销和推送集中在这个时段。
5. 收藏信号利用。收藏用户转化率高 5 个百分点，可以对"已收藏未购买"的用户做定向促购。
6. 类目流量再平衡。高曝光低转化的类目（2355072、3607361、4756105）优化承接，高转化类目（2885642、2735466）加流量。

## 七、行业基准对比

行业数据是 2024 年的，我这个数据集是 2017 年的，时间和口径都对不齐，所以对比只给区间、看相对位置，不拿单点硬比。

- QuestMobile《2024年移动互联网春季报告》：移动购物行业月活跃用户 10.73 亿（2024年3月，同比增长 5.7%），全网中高消费意愿用户占比突破 75%。来源为四川经济日报转载，访问日期 2026-08-10。
- 商务部电子商务司《2024年我国电子商务发展情况》：2024 全年网上零售额同比增长 7.2%，实物网零拉动社零增长 1.7 个百分点。来源为新浪财经转载，访问日期 2026-08-10。
- 艾瑞咨询《2024年中国电商市场研究报告》：报告页确认存在（report.iresearch.cn/report/202409/4388.shtml，2024/9/30 发布）。免费简介里没有具体转化率数字，仅作研究参考。

| 本项目指标 | 数值 | 口径 | 与行业对比 |
|---|---|---|---|
| 事件级 PV→购买转化率 | 2.237%（200,830 / 8,976,117） | 事件级（次数比次数） | 可直接对标行业页面级 2-5%，落在区间内 |
| 全链路转化率 | 31.42% | 用户级 | 与行业页面级指标不可直接比较 |
| 用户付费率 | 68.14%（67,319 / 98,798） | 用户级 | 同上 |

用户级指标没法跟行业比。这份数据集只包含"产生过行为"的用户，纯浏览退出的访客早就被筛掉了，用户级指标必然偏高。真正能拿去比的是事件级的 2.237%。

## 八、局限

| 局限 | 说明 |
|---|---|
| 数据时效 | 2017 年 9 天窗口的公开数据集，不是实时数据 |
| 无金额字段 | 高价值用户贡献度用购买次数近似，不是 GMV |
| 留存不可用 | 数据集末尾两天接近全员活跃（12-02 占 98.2%），抽样框锚定窗口末尾，cohort 留存不产出业务结论，见 5.5 |
| 星期维度受限 | 9 天窗口内各星期出现天数不等（周末 2 天、工作日 1 天），且末尾两天活跃度突变，只能按日均比较并剔除异常日 |
| R 档区分度 | 窗口只有 9 天，R 最大到 8，1 档没有用户；高价值分层实际主要由 F（购买频次）驱动 |
| 抽样口径 | 全部数字都是 10% 抽样口径，总量类指标外推要注意 |
| 注册定义 | 数据集没有注册字段，用"首次行为日"近似 |
| 行业对比 | 行业数据 2024 年，本项目 2017 年，给区间看相对位置 |
